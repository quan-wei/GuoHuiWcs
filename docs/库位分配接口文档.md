# 库位分配接口文档

## 基础信息

- Base URL: `/api/Location`
- Content-Type: `application/json`
- 所有分配接口均 **不需要传 `PallNo`**，系统自动通过 `serialsequence` 表生成流水号托盘编号（格式 `PALL` + 日期 + 4位序号，如 `PALL202608060001`）

---

## 1. 自动分配库位

系统自动查找空闲库位并分配，优先一层货架，不满足则向上层货架（二层→三层→四层）查找。

**请求**

```
POST /api/Location/allocate
Content-Type: application/json
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `MaterNo` | `string[]` | 是 | 物料条码列表，用于从 WMS 同步物料重量 |
| `StartPoint` | `string` | 是 | 起点（货架编号），AGV 搬运起点 |
| `EndPoint` | `string` | 否 | 终点，通常留空 |
| `TaskType` | `string` | 否 | 任务类型标识 |
| `AllowUpperLevels` | `bool` | 否 | 是否允许上层货架，默认 `true` |

**请求示例**

```json
{
    "MaterNo": ["BARCODE001", "BARCODE002"],
    "StartPoint": "G2",
    "EndPoint": "",
    "TaskType": "入库",
    "AllowUpperLevels": true
}
```

**成功响应** `200`

```json
{
    "Success": true,
    "LocationCode": "A01-01-01",
    "LocationType": "一层货架",
    "WeightKg": 150.5,
    "PallNo": "PALL202608060001",
    "Message": "分配成功"
}
```

**失败响应** `400`

```json
{
    "Success": false,
    "Message": "无可用库位：一层已满，且上层库位均不满足重量限制"
}
```

**处理流程**

1. 校验 `StartPoint` 不为空
2. 调用 `GeneratePallNo()` 生成托盘号
3. 遍历 `MaterNo`，逐条调 WMS 接口同步物料重量
4. 按 「一层货架 → 二层货架 → 三层货架 → 四层货架」 顺序查找空闲可用库位
5. 分配库位（UPDATE status），插入 `PallMater` 记录
6. 调用 AGV 创建搬运任务（起点 → 分配库位）
7. AGV 失败则自动回滚：释放库位 + 删除 PallMater 记录

## 2. 分配到指定库位

将托盘分配到调用方指定的库位，不走自动查找逻辑，直接校验目标库位是否可用。

**请求**

```
POST /api/Location/allocate/{locationCode}
Content-Type: application/json
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| `locationCode` | Path | `string` | 是 | 目标库位编码，如 `A01-02-03` |

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `MaterNo` | `string[]` | 是 | 物料条码列表 |
| `StartPoint` | `string` | 否 | 起点（货架编号），建议传入 |
| `EndPoint` | `string` | 否 | 终点 |
| `TaskType` | `string` | 否 | 任务类型标识 |
| `AllowUpperLevels` | `bool` | 否 | 此接口不使用该字段 |

**请求示例**

```
POST /api/Location/allocate/A01-02-03

{
    "MaterNo": ["BARCODE003"],
    "StartPoint": "G01",
    "EndPoint": "A01-02-03",
    "TaskType": "入库"
}
```

**校验规则（按顺序）**

| 校验项 | 失败提示 |
|------|------|
| 库位存在 | 终点库位不存在 |
| 库位空闲（Status=0 且 PallNo 为空） | 终点库位已被占用 |
| 库位已启用 | 终点库位已禁用 |
| 非地面库位 | 地面中转库位，不可用于存储分配 |
| 所在货架组上层重量 ≤ 2500kg | 所在货架对已超重限制 |

**成功响应** `200`

```json
{
    "Success": true,
    "LocationCode": "A01-02-03",
    "LocationType": "二层货架",
    "WeightKg": 80.0,
    "PallNo": "PALL202608060002",
    "Message": "分配成功"
}
```

**失败响应** `400`

```json
{
    "Success": false,
    "Message": "终点库位已被占用"
}
```

**处理流程**

1. 校验 `MaterNo` 不为空
2. 调用 `GeneratePallNo()` 生成托盘号
3. 查询目标库位，逐个校验（存在→空闲→启用→非地面库位）
4. 同步 WMS 获取物料重量
5. 插入 `PallMater` 记录
6. 检查货架组重量上限（≤ 2500kg）
7. 分配库位（UPDATE status）
8. 调用 AGV 创建搬运任务
9. AGV 失败则自动回滚

## 3. 释放库位

将指定库位置为空闲状态。

**请求**

```
POST /api/Location/release/{locationCode}
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| `locationCode` | Path | `string` | 是 | 要释放的库位编码 |

**成功响应** `200`

```json
{
    "Success": true,
    "Message": "库位已释放"
}
```

**失败响应** `400`

```json
{
    "Success": false,
    "Message": "库位释放失败，可能已是空闲状态"
}
```

---

## 4. 查询货架组负载

查询指定货架所在组的当前重量负载。

**请求**

```
GET /api/Location/group-load/{shelfCode}
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| `shelfCode` | Path | `string` | 是 | 货架编号 |

**成功响应** `200`

```json
{
    "GroupShelfs": ["1", "2"],
    "CurrentWeightKg": 320.0,
    "LimitWeightKg": 2500.0,
    "RemainingWeightKg": 2180.0,
    "TierLoads": {
        "二层货架": 120.0,
        "三层货架": 200.0,
        "四层货架": 0.0
    }
}
```

## 两个分配接口的差异对比

| | 自动分配 | 指定分配 |
|------|------|------|
| 路径 | `POST /api/Location/allocate` | `POST /api/Location/allocate/{locationCode}` |
| 库位选择 | 系统自动查找空闲库位 | 调用方指定 |
| 查找策略 | 一层 → 二层 → 三层 → 四层 | 不查找，直接逐项校验 |
| 重量校验时机 | 分配时检查 | 分配前检查 |
| 适用场景 | 常规入库，无需关心具体库位 | 指定目的地搬运、返库、调试等 |

---

## 通用说明

- 分配成功后会自动创建 AGV 搬运任务（起点 → 库位），AGV 失败则自动回滚库位分配并删除托盘记录
- 托盘号由系统自动生成，调用方无需传入，响应中会返回生成的 `PallNo`
- 上层货架（二/三/四层）以货架组为单位校验重量，每组上限 2500kg
- 货架组规则：相邻两个货架编号为一组（奇数 N 与 N+1）
- 地面库位仅用于中转，不参与存储分配
